# TRTTT

لوحة خاصة بالمالك لإنشاء فواتير وروابط دفع عبر EdfaPay، مع إحصائيات، والتخزين في Firestore.

## متغيرات البيئة في Render

| المتغير | القيمة |
| --- | --- |
| `OWNER_NUMBER` | رقم المالك المستخدم في تسجيل الدخول |
| `OWNER_PASSWORD` | كلمة المرور، 10 خانات على الأقل |
| `SECRET_KEY` | نص عشوائي من 32 خانة أو أكثر (زر Generate في Render) |
| `ENCRYPTION_KEY` | نص عشوائي من 32 خانة أو أكثر. لا تغيّره بعد التشغيل وإلا تعذرت قراءة بيانات العملاء المحفوظة |
| `FIREBASE_CREDENTIALS` | محتوى ملف مفتاح حساب الخدمة من Firebase بصيغة JSON |
| `EDFAPAY_MERCHANT_ID` | معرف التاجر من إعدادات التكامل في لوحة EdfaPay |
| `EDFAPAY_MERCHANT_PASSWORD` | كلمة مرور التاجر من إعدادات التكامل في لوحة EdfaPay |

إن كان حسابك في EdfaPay يعمل بمفتاح API بدل معرف التاجر وكلمة المرور، ضع `EDFAPAY_API_KEY` و
`EDFAPAY_WEBHOOK_SECRET` و `EDFAPAY_ENV` (`sandbox` أو `production`) بدلاً منهما.

اختياري: `STORE_NAME` اسم المتجر الظاهر للعميل، `BASE_URL` رابط الموقع إن استخدمت نطاقاً خاصاً،
`EDFAPAY_BASE_URL` لتغيير عنوان واجهة EdfaPay، `OWNER_PASSWORD_HASH` بديلاً عن كلمة المرور النصية.

إذا نقص متغير مطلوب يتوقف الموقع ويعرض أسماء المتغيرات الناقصة.

## الإيميل (اختياري)

| المتغير | القيمة |
| --- | --- |
| `SMTP_SERVER` | خادم البريد، مثل `mail.privateemail.com` |
| `SMTP_PORT` | `465` أو `587` |
| `SMTP_EMAIL` | الإيميل الذي تُرسل منه الرسائل |
| `SMTP_PASSWORD` | كلمة مرور ذلك الإيميل |
| `OWNER_EMAIL` | إيميلك أنت: يصله رمز الدخول وإشعار كل دفعة |

- **تسليم الطلب:** اكتب في الفاتورة ما يُرسل للعميل (كود شحن، رابط تحميل...). يُحفظ مشفّراً، ويصل إلى بريد العميل
  مرة واحدة بعد أن يؤكد EdfaPay الدفع. حالة الإرسال وزر إعادة الإرسال في صفحة الفاتورة.
- **إشعار الدفع:** يصلك إيميل بكل دفعة مؤكدة.
- **رمز الدخول:** يُفعَّل من صفحة الإعدادات بعد تجربة رمز يصل فعلاً إلى `OWNER_EMAIL`. بعدها يُطلب الرمز بعد كلمة المرور.
  إن تعطل الإيميل فاحذف `OWNER_EMAIL` من Render مؤقتاً لتدخل بكلمة المرور وحدها.

تنبيه: الخطة المجانية في Render تمنع الاتصال بمنافذ البريد 25 و 465 و 587، فالإيميل يحتاج أن تكون الخدمة على خطة مدفوعة.
زر «إرسال رسالة تجريبية» في صفحة الإعدادات يوضح إن كان الإرسال يعمل.

## إعداد Render

- Build Command: `pip install -r requirements.txt`
- Start Command: `gunicorn app:app --workers 2 --threads 4 --timeout 60`
- Health Check Path: `/healthz`

## إعداد EdfaPay

سجّل الدخول إلى الموقع وانسخ الرابط الظاهر في قسم «ربط EdfaPay» أسفل اللوحة، ثم ضعه في خانة لينك الكول باك
في إعدادات التكامل بلوحة EdfaPay. الفاتورة لا تصبح مدفوعة إلا بعد أن يؤكد EdfaPay نفسه أن العملية مسددة.

## الحماية

- الدخول برقم المالك وكلمة المرور فقط، مع قفل 15 دقيقة بعد 5 محاولات خاطئة.
- بيانات العميل ووصف الفاتورة تُشفَّر بـ AES-256-GCM قبل حفظها في Firestore.
- دفتر العملاء مشفّر بالطريقة نفسها، والعميل يُعرَف ببصمة مشفّرة لرقم جواله لا بالرقم نفسه.
- كل إشعار دفع يُراجَع مع EdfaPay مباشرة مع مطابقة رقم الطلب والمبلغ قبل اعتماد الدفع.
- رمز الدخول بالإيميل اختياري: لا يُحفظ الرمز نفسه بل بصمة مشفّرة له، وينتهي بعد 10 دقائق أو 5 محاولات خاطئة.
- الطلب الذي يُرسل للعميل مشفّر في Firestore، ولا يظهر في صفحات العميل ولا في السجلات.
- لا يوجد أي سر داخل المستودع، وكل الأسرار في متغيرات البيئة.
